# Image Processor

세 가지 도구가 탭으로 나뉘어 있어요.

- **이미지 압축**: 고화질 이미지를 웹용으로 자동 최적화 (크기 줄이기 + 가벼운 형식으로 변환)
- **이미지 자르기**: 긴 이미지를 가로로 잘라 여러 조각으로 나누기 (버튼 부분만 따로 잘라 링크 걸 때)
- **썸네일 만들기**: 배너 이미지를 233×158, 216×158 같은 정해진 크기의 썸네일로 만들기 (크기는 바꿀 수 있어요)

모든 처리는 **사용자의 브라우저 안에서** 이루어져서 서버가 필요 없고, 이미지가 밖으로 전송되지 않아요.

## 실행 방법

ES 모듈(`import`/`export`)을 쓰기 때문에 `index.html`을 더블클릭해서 열면 **동작하지 않아요.**
(브라우저 보안 정책상 `file://` 주소에서는 모듈을 불러올 수 없어요.)
아래 방법 중 하나로 간단한 로컬 서버를 띄워주세요.

- **가장 쉬운 방법 (macOS)**: 폴더 안의 `start.command`를 더블클릭 → 브라우저가 자동으로 열려요. (끌 때는 터미널 창 닫기)
- **VS Code**: 확장 프로그램 "Live Server" 설치 → `index.html` 우클릭 → *Open with Live Server*
- **터미널**: 이 폴더에서 `python3 -m http.server 8000` 실행 → 브라우저에서 http://localhost:8000

주소 끝에 `#slice`나 `#thumb`를 붙이면 그 탭이 바로 열려요. (예: http://localhost:8000/#thumb)

## 이미지 자르기 사용법

1. **이미지 자르기** 탭에 긴 이미지를 끌어다 놓기
2. 자르고 싶은 위치를 **클릭** → 분홍색 자르는 선이 생겨요
   - 선을 **끌어서** 옮기기. `Shift`를 누른 채 끌면 **10px씩** 움직여요 (선 옆에 `+30`처럼 이동량 표시)
   - 선을 선택하고 `↑` `↓`로 1px씩 (`Shift`와 함께 10px) 조정
   - 끄는 중 화면 위·아래 끝에 대면 저절로 스크롤돼요
   - 오른쪽 **보기**의 `+` `−` `100%` 또는 `⌘`(Windows는 `Ctrl`) + 휠 / 트랙패드 핀치로 **확대**해서 정밀하게 맞출 수 있어요
     (200% 이상에서는 픽셀 경계가 또렷하게 보여요. `맞춤`으로 돌아가기)
   - 오른쪽 목록에서 **px 숫자를 직접 입력**해도 돼요
   - 선 옆 `×` 또는 `Delete` 키로 삭제
3. 버튼 조각은 오른쪽 목록에서 **버튼**에 체크 → 파일 이름에 `_btn`이 붙어요
4. **조각 ZIP 다운로드** → `원본이름_01.jpg`, `원본이름_02_btn.jpg`, `원본이름_03.jpg` …

> 버튼이 맨 아래에 있으면 선 1개(조각 2개), 중간에 있으면 버튼 위·아래로 선 2개(조각 3개)를 그으면 돼요.

## 썸네일 만들기 사용법

1. **썸네일 만들기** 탭에 이미지를 끌어다 놓기 (여러 장 가능)
2. 설정한 크기마다 썸네일이 바로 만들어져요
   - 원본과 썸네일의 가로세로 비율이 다르면 넘치는 부분은 **가운데 기준으로** 잘라요
   - 크기는 설정에서 숫자를 고치거나 **+ 크기 추가**로 늘릴 수 있어요 (브라우저에 기억돼요)
3. **세로로 긴 이미지**(상세페이지 등)라면 카드의 **부분 선택** → 썸네일로 쓸 부분만 고르기
   - 처음엔 맨 위 부분으로 만들어져 있고, 카드에 안내가 떠요
   - 이미지 위를 **끌어서** 부분을 그리기 (창 위·아래 끝으로 끌면 저절로 스크롤)
   - 그린 부분은 안쪽을 끌어 옮기고, 변·모서리를 끌어 크기 조절 (비율 자유)
   - **이 부분 사용**을 누르면 모든 썸네일 크기가 그 부분 안에서 다시 가운데로 맞춰져요
4. 글자가 잘렸다면 그 썸네일을 **클릭** → 영역 조정 창
   - 영역을 **끌어서** 옮기기, **모서리**를 끌거나 **휠**로 확대·축소
   - 영역 밖을 누르면 그 자리로 이동, 키보드 `←↑↓→`로 1px씩 (`Shift`와 함께 10px)
   - 위쪽 크기 버튼으로 다른 크기도 이어서 조정할 수 있어요
5. **전체 ZIP 다운로드** → `원본이름_233x158.jpg`, `원본이름_216x158.jpg` …

> 레티나 화면에서 더 선명하게 보이게 하려면 2배 크기(466×316, 432×316)를 추가해서 그걸 쓰면 돼요.

### 왜 이렇게 나눴나요?

**1. "화면"과 "로직"을 분리**

- `image/` 폴더는 버튼이나 HTML을 하나도 몰라요. 파일을 받아서 파일을 돌려줄 뿐이에요.
  → 나중에 디자인을 완전히 바꿔도 이미지 처리 코드는 그대로 쓸 수 있어요.
- `ui/` 폴더는 압축이 어떻게 되는지 몰라요. 데이터를 받아 그리고, 클릭되면 알려줄 뿐이에요.

**2. "같은 흐름"과 "처리 방법"을 분리**

압축 탭은 *파일 받기 → 목록 → 한 장씩 처리 → 결과 표시 → 선택·삭제·ZIP* 흐름이에요.
이 흐름은 어떤 "자동 처리" 탭이든 똑같고, 달라지는 건 **"이미지 한 장을 어떻게 처리하느냐"** 하나뿐이에요.

- 같은 흐름 → `workspace.js`에 한 번만 작성
- 처리 방법 → `main.js`의 `compressPipeline` 함수로 작성해서 넘겨줌

같은 방식의 새 탭(예: 형식 변환)을 만들고 싶다면, HTML에 패널을 하나 추가하고
`main.js`에 파이프라인 함수 하나만 새로 쓰면 돼요.

**3. 흐름이 다른 탭은 따로**

자르기 탭은 *여러 장을 자동 처리*가 아니라 *한 장을 열어 사람이 선을 긋는* 편집 방식이라
`workspace.js`를 쓰지 않고 `ui/slicer.js`로 따로 만들었어요. 대신 같은 규칙은 그대로 지켜요.

- 선 데이터 규칙 → `cuts.js` (화면·이미지 처리 모두 모름)
- 실제로 자르기 → `image/slice.js` (화면 모름)
- 화면 → `ui/slicer.js` (자르는 방법 모름)
- 형식·품질 설정, 드롭 영역, ZIP은 다른 탭과 같은 코드(`settings.js`, `dropzone.js`, `zip.js`)를 재사용
- `slicer`도 `addFiles()`를 갖고 있어서, `main.js`의 "아무 데나 놓기·붙여넣기"가 탭 종류를 몰라도 똑같이 동작해요

**4. 썸네일 탭도 같은 규칙으로**

썸네일 탭은 "넣으면 자동 처리"와 "사람이 직접 조정"이 섞여 있어서 역시 따로 만들었어요.

- 영역 데이터 규칙 → `crop.js` (비율이 절대 안 바뀌고, 원본 밖으로 안 나가고, 썸네일보다 작아지지 않게)
- 긴 이미지는 두 단계로 잘라요: ① `region.js` 사용할 부분(비율 자유) → ② `crop.js` 썸네일 영역(비율 고정).
  ①을 고르면 그 부분을 잘라 "작업용 이미지"를 새로 만들기 때문에, ②쪽 코드는 ①이 있는지 전혀 몰라요.
- 실제로 자르고 줄이기 → `image/thumbnail.js` (화면 모름)
- 화면 → `ui/thumbnailer.js`(목록) · `ui/cropper.js`(조정 창) · `ui/sizes.js`(크기 편집)
- 형식 설정, 드롭 영역, ZIP, 고품질 축소(`canvas.js`의 `resize`)는 기존 코드 재사용
- 품질 선택은 없어요. 썸네일은 작아서 항상 고화질(95)로 저장해요 (`thumbnailer.js`의 `QUALITY`)

```

        │

                        ▼
                    enqueue()  ── 탭마다 따로 있는 대기열 (한 장씩 차례로)
                        │
                        ▼
                    processItem()
                        │  settings.read()       이 탭의 설정 읽기
                        │  process(...)          ← main.js가 넘겨준 파이프라인
                        │
                        │   ┌ 압축 탭 ───────────────────────────────┐
                        │   │ image/compress.js  줄이기 + 형식 변환   │

```

## 추천 공부 순서

1. **`js/main.js`**: 파이프라인 함수와 탭 연결을 보면 앱 전체 구조가 한눈에 보여요.
2. **`js/workspace.js`의 `processItem()`**: 파이프라인이 언제, 어떻게 불리는지
3. **`js/image/canvas.js`**: 브라우저에서 이미지를 다루는 기본 3단계 (디코딩 → 그리기 → 인코딩)
4. **`js/image/compress.js`**: 용량이 줄어드는 원리
5. **`js/store.js`**: 데이터를 한 곳에서 관리하는 이유, 팩토리 함수, 메모리 정리 (Object URL)
6. **`js/ui/*`**: 데이터를 화면으로 그리는 방법, 탭 접근성
7. **`js/cuts.js` → `js/image/slice.js` → `js/ui/slicer.js`**: 데이터 규칙 → 처리 → 화면 순서로 자르기 기능 따라가기
8. **`js/crop.js` → `js/image/thumbnail.js` → `js/ui/cropper.js`**: 썸네일 영역 규칙 → 자르고 줄이기 → 끌어서 조정하는 화면
   그다음 `js/region.js` → `js/ui/region-picker.js` → `js/ui/thumbnailer.js`의 `applyRegion()`: 긴 이미지 부분 선택

## 코드에서 만나는 주요 개념

| 개념 | 한 줄 설명 | 나오는 곳 |
|---|---|---|
| ES 모듈 (`import`/`export`) | 파일끼리 함수를 주고받는 표준 방법 | 모든 파일 |
| `async` / `await` / Promise | 오래 걸리는 작업을 기다리는 방법 | 거의 모든 파일 |
| 팩토리 함수 + 클로저 | 함수를 부를 때마다 독립된 상태를 가진 객체를 새로 만듦 | `store.js`, `workspace.js` |
| 전략(strategy) 패턴 | 바뀌는 부분만 함수로 받아서 끼워 넣기 | `workspace.js`의 `process` |
| Promise 체인 대기열 | `.then()`으로 이어서 작업을 하나씩 순서대로 | `workspace.js` `enqueue()` |
| `<canvas>` | 코드로 그림을 그리는 도화지. 리사이즈·형식 변환에 사용 | `image/canvas.js` |
| Blob / File | 브라우저 메모리 안의 파일 데이터 | `store.js`, `image/*` |
| Object URL (`blob:...`) | Blob을 `<img>`에 쓰기 위한 임시 주소. 다 쓰면 해제해야 함 | `store.js` |
| AbortController | 진행 중인 작업을 중간에 멈추는 표준 도구 | `workspace.js`, `store.js` |
| data 속성 | `id` 대신 `data-setting="format"`처럼 표시해서 탭마다 같은 구조를 찾음 | `ui/settings.js`, `workspace.js` |
| 이벤트 전파 (`stopPropagation`) | 같은 drop 이벤트가 두 번 처리되지 않게 막기 | `ui/dropzone.js` |
| ARIA 탭 패턴 | 스크린 리더·키보드 사용자도 탭을 쓸 수 있게 | `ui/tabs.js` |
| `drawImage` 9개 인자 | 원본의 일부분만 잘라 그리기 (크롭) | `image/slice.js` |
| Pointer Events + `setPointerCapture` | 마우스·터치를 한 코드로, 끌기 중 커서가 벗어나도 계속 추적 | `ui/slicer.js` |
| % 좌표 | 원본 px을 %로 바꿔 배치하면 화면 크기가 바뀌어도 다시 계산할 필요 없음 | `ui/slicer.js` |
| 시작점 + 이동량 끌기 | 잡은 위치와 선이 어긋나도 튀지 않게, Shift면 이동량을 10 단위로 반올림 | `ui/slicer.js` `applyDrag()` |
| 기준점 유지 확대 | 확대 전후로 커서 아래 지점이 같은 화면 위치에 오도록 스크롤 보정 | `ui/slicer.js` `setZoom()` |
| CSS 변수로 위치 전달 | JS가 `--view-left` 값만 알려주고 배치는 CSS가 `calc()`로 | `ui/slicer.js` · `style.css` |
| 이벤트 위임 | 매번 새로 그려지는 목록은 부모에 이벤트를 한 번만 달기 | `ui/slicer.js` |
| 덕 타이핑 | 쓰는 법(`addFiles`)만 같으면 종류가 달라도 같은 자리에 끼울 수 있음 | `main.js` |
| 상태 → render() | 상태를 바꾸고 화면은 전부 다시 그리는 패턴 | `ui/preview.js` |
| `textContent` vs `innerHTML` | 사용자 입력은 항상 textContent로 (보안) | `ui/list.js` |
| 비율 고정 영역 | 가로만 정하면 세로는 자동 (h = w ÷ 비율). 모든 변경을 함수 하나(`set`)로 모아 규칙을 지킴 | `crop.js` |
| 초점 기준 확대 | 휠로 확대해도 커서 아래 지점이 제자리에 머물게 계산 | `crop.js` `zoomTo()` |
| `requestAnimationFrame` | 끄는 동안 쏟아지는 이벤트를 화면 갱신 1번에 1번만 그리도록 모으기 | `ui/cropper.js` |
| `ResizeObserver` | 요소 크기가 바뀔 때마다 알려줌. 창 크기에 맞춰 이미지 틀 다시 계산 | `ui/cropper.js` |
| 큰 `box-shadow`로 바깥 어둡게 | 구멍에 9999px 그림자 + `overflow: hidden`으로 자르기 | `style.css` (`.cr-shade`) |
| 끄는 중 저절로 스크롤 | 포인터가 멈춰도 스크롤되도록 rAF로 매 프레임 끝 근처인지 확인 | `ui/region-picker.js` `autoScroll()` |
| 두 단계 자르기 | 먼저 자른 결과를 "새 원본"처럼 넘기면 다음 단계 코드는 바꿀 필요가 없음 | `ui/thumbnailer.js` `applyRegion()` |
| `wheel` + `passive: false` | 휠 이벤트에서 페이지 스크롤을 막으려면 미리 알려야 함 | `ui/cropper.js` |
